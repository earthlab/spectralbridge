A separate startup issue was observed in the isolated extraction test: `_require_pyarrow_parquet()` accesses `pyarrow.parquet` without importing that submodule, which raises AttributeError in a fresh process until `import pyarrow.parquet` has run. The overlap reproduction imports it explicitly to reach the extraction loop. Recommended fix: import the submodule in the lazy helper. This is an execution/import-order issue, not evidence that the already completed analysis was wrong.

Wavelength precision boundary: inline sensor centers/FWHM are loaded as float32 from the packaged decimal JSON. Polygon extraction rounds wavelength labels to integer nm; those labels do not encode the original decimal response centers or full response functions. Reconstruct operators from authoritative metadata, not rounded column names. No coefficient direction error was found in the inspected wavelength-mapped affine application.

Other checks: actual Landsat Collection2 scaling is affine `2.75e-5 DN−.2` only on documented DN domain; spectral units remain unresolved for the historical library. Drone translation direction is explicitly target=slope×source+intercept and wavelength-mapped, not the inverse packaged percentage transform. Negative finite corrected values are not universally nodata. Gap-aware interpolation excludes 1340–1450/1790–2000 nm and refuses >8nm bridges; scalar and matrix claims require identical support. Labels are the five recorded categories, not inferred purity/species/PFT truth. No standardization leakage was found in the audited benchmark's proper/calibration/target code; this is code/evidence inspection, not a Lean workflow proof.

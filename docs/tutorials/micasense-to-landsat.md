SpectralBridge includes MicaSense-related sensor outputs and brightness
coefficient tables, and the drone workflow can process local HDF5 exports while
preserving drone-native provenance. Parquet remains the authoritative tabular
output; CSV sidecars from the drone path are convenience copies only.

---

## Current supported entry points

Use the drone pipeline from Python when working with local drone HDF5 exports:

```python
from spectralbridge.pipelines.drone import run_drone_pipeline

results = run_drone_pipeline(
    input_h5_dir="path/to/drone_h5_exports",
    polygon_path="Datasets/niwot_aop_polygons_2023_12_8_23_analysis_ready_half_diam.gpkg",
    output_dir="drone_outputs",
)
```

The drone workflow writes per-flight outputs such as:

```text
<flight_stem>__envi.img/.hdr
<flight_stem>__corrected.img/.hdr
<flight_stem>__polygons.parquet
<flight_stem>__qa.png
<flight_stem>__qa.json
drone_merged.parquet
drone_qa_summary.json
```

---

## How this relates to Landsat-style products

For NEON flight lines, Landsat-style products are generated by the standard
sensor resampling stage and use names such as:

```text
*_landsat_tm_envi.img
*_landsat_oli_envi.img
*_micasense_envi.img
*_micasense_to_match_oli_oli2_envi.img
```

Those outputs are documented in [Outputs & file structure](../pipeline/outputs.md).

  <section class="sb-doc-section" markdown="1">
    <p class="sb-kicker">Canonical usage</p>
    <h2>Most users should start here</h2>

```python
from spectralbridge import go_forth_and_multiply

go_forth_and_multiply(
    base_folder="output_demo",
    site_code="NIWO",
    year_month="2023-08",
    product_code="DP1.30006.001",
    flight_lines=[
        "NEON_D13_NIWO_DP1_L020-1_20230815_directional_reflectance",
    ],
    max_workers=1,
    engine="thread",
)
```

    <p>This follows the same ordered, restart-safe contract as the CLI and writes the same on-disk outputs.</p>

    <h2>What is intentionally public?</h2>
    <div class="sb-doc-grid sb-doc-grid--two">
      <article class="sb-doc-card">
        <h3><code>go_forth_and_multiply</code></h3>
        <p>Batch-oriented NEON orchestration including download, export, correction, harmonization, parquet writing, merge, and QA.</p>
      </article>
      <article class="sb-doc-card">
        <h3><code>process_one_flightline</code></h3>
        <p>Single-flightline execution with explicit knobs for chunk size, merge behavior, polygon options, and engine choice.</p>
      </article>
      <article class="sb-doc-card">
        <h3><code>run_drone_pipeline</code></h3>
        <p>Local drone processing path with QA, polygon support, and mixed HDF5/TIFF source handling.</p>
      </article>
      <article class="sb-doc-card">
        <h3><code>apply_brightness_correction</code></h3>
        <p>Lower-level reflectance adjustment helper used when you need targeted brightness normalization logic outside the main pipeline.</p>
      </article>

  <section class="sb-doc-section" markdown="1">
    <p class="sb-kicker">API philosophy</p>
    <h2>How to think about the Python surface</h2>
    <ul class="sb-doc-list">
      <li>Prefer the top-level orchestrators over stitching internal helpers together yourself.</li>
      <li>Treat output files and naming conventions as part of the public contract.</li>
      <li>Use tests and nearby docs to distinguish stable entry points from implementation details.</li>
      <li>Expect idempotent, restart-safe behavior rather than pure in-memory return-value workflows.</li>
    </ul>
